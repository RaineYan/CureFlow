# 修正后的增量 AI 解读

## 使用方式

1. 在桌面工作台对文件执行一次 AI 解读，建立本机的证据依赖记录。
2. 在“修正与复测”中核对问题，导出并载入修正版。
3. 保持相同模型、分析目标、字段设置及背景问题，执行复测。
4. 在“AI 结论更新”查看保留条目、重新生成条目、本次调用次数和模型上报用量。

旧版本生成的分析没有依赖记录，需要先完整分析一次。直接换一个文件，不等同于已授权修正版，不能据此复用旧结论。

## 执行规则

- 服务端核验修正版授权、来源输入指纹、本地工具签名、证据版本和有效状态。
- AI 结论与建议逐条绑定引用。只有引用全部仍有效、证据投影与实际产物哈希完全相同时才保留条目。
- 变动的证据块组成增量请求；未变证据块和旧解读不重复发送给模型。合并后再次校验全部引用，摘要在本机重组，不沿用旧总摘要。
- 全部证据未变且有可复用结论时，不调用模型。本次用量为零，不把历史调用用量重复计费。
- 模型、问题、字段设置、方法前提或数据充分性变化，记录缺失或损坏、人工修改过来源解读、依赖无法追踪时，保守地执行完整解读。
- 当前证据失效，或生成期间证据/人工复核记录变化时，阻止展示增量合并结果；不会自动增加付费重试。
- 保留原有 findings/actions 数量与引用校验约束。超出合并容量不会截掉断言来让测试通过。

## 隐私与计量

依赖记录保存在本机数据目录的 `ai_dependency_manifests`，包含已生成解读、输入指纹、模型身份及证据哈希，不保存密钥，也不额外保存原始数据行。AI 请求仍遵循现有最小证据投影边界。

`aiRecovery` 记录执行模式、复用/生成数量、完整与本次发送的证据字节数；`cost` 只记录本次调用。字节数不是 token 数，本地少执行几个工具也不算 token 节省。

模型没有返回可靠 usage 时，界面显示用量未知。没有对同一修正版、同一模型执行完整重跑对照时，不给出 token 节省百分比。离线测试中的模拟 usage 仅验证计量逻辑，不能作为真实节省实验数据。

## 范围

覆盖桌面单表与工作簿的通用证据解读链路；不修改冻结实验或历史经营指标专用流水线。复用粒度是带引用的结论/建议与本地工具证据块，不声称同一工具块内部每个字段都已拆成独立 AI 请求。
