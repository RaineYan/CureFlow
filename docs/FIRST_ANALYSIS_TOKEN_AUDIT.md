# 首次分析是否节省 token：当前审查结论

审查日期：2026-10-19。范围：当前桌面通用分析链路，不是冻结的历史恢复实验。

## 结论

目前没有同一数据、同一任务、同等输出要求下的配对真实调用，因此不能宣称 CureFlow 首次分析比直接使用豆包、DeepSeek、OpenAI 或其他工具更省 token。

CureFlow 是数据分析工作流，不是独立训练的基础模型。首次分析的潜在收益来自“本机计算后只发送必要摘要”，不是旧结论复用。修正后的增量解读是另一项机制，不能算到首次分析的收益里。

## 本次实际检查

用程序生成 4 列、10 / 100 / 1,000 / 10,000 行的非用户 CSV，经过实际 `/api/analyze` 处理，目标为 `exploratory_analysis`。在模型调用边界替换为离线记录器，捕获完整应用提示词；没有读取或使用真实 API Key，没有向模型发送数据，也没有产生真实模型调用费用。记录器的输出只用于让接口完成，不能用于评价分析质量。

| 生成数据行数 | 原始 CSV 字符数 | 应用提示词字符数 | 证据 JSON 字符数 | 捕获的应用调用次数 |
| --- | ---: | ---: | ---: | ---: |
| 10 | 232 | 12,102 | 10,836 | 1 |
| 100 | 2,085 | 11,851 | 10,585 | 1 |
| 1,000 | 20,576 | 11,865 | 10,599 | 1 |
| 10,000 | 205,579 | 11,875 | 10,609 | 1 |

计量口径：Python `len(str)` 的 Unicode 字符数。原始 CSV 不含分析指令；CureFlow 列包含应用规则与证据。因此这张表是输入体积诊断，不是公平的模型性能或 token 节省实验。它也不包含适配器另加的 system 消息、输出 token 或思考 token。更宽的表格、更多问题及不同方法包也可能改变请求体积，不能推广为所有数据的固定上限。

发现的主要开销：本例方法依据包约 4,848–4,854 字符，规则及证据封装约 1,266 字符，另外还有工具结果、通用指标、数据充分性与修正摘要。大型表格的行数据可以被摘要压缩，但小表格可能因这些固定开销反而增加输入。当前不能把字符差额换算成实际 token 节省率。

## 历史日志与证据边界

本机既有审计包含多家 Provider 上报的 usage，但不是同一文件、同一任务、同一输出要求的配对记录，不能据此排名。这些运行日志、文件、请求 ID 和用户数据不随本报告上传。

历史 EXP-02 的 FULL / SELECTIVE 比较针对修正或故障后的恢复策略，不是当前桌面版首次分析对比，也不能替代首次分析的实验。

## 可复现离线检查

从仓库根目录运行：

```powershell
python scripts/audit_first_analysis.py
```

脚本只使用生成数据和离线模型记录器。输出中的 `capturedCalls` 是被拦截的应用调用次数，`networkCalls` 为 0，不是付费调用结果。若本机存在历史审计，脚本还会输出 usage 数值范围，不输出原始表格或请求 ID。

## 后续公平比较方案（尚未执行）

1. 先固定同一个实际模型，分别使用“原表直接分析”和“CureFlow 本地统计摘要分析”，排除更换模型造成的混淆。
2. 使用获授权的去标识化数据和相同分析问题、输出长度要求；统计正确性、问题覆盖和证据可核对性也要对照，不能用遗漏内容换取更少 token。
3. 分别报告输入、输出、思考及缓存明细，避免重复相加；记录失败、重试和总费用。缓存折扣不等于 token 数量减少。缺少 usage 的运行不算作零消耗。
4. 两次调用只能作为单个文件的初测；正式结论需要多类数据、规模和重复测量。之后再在各 Provider 内做配对比较，不直接把不同模型的 token 数差异归因于 CureFlow。
5. 真实调用会发送数据并产生费用，须另获用户对文件、模型和调用预算的授权。本次没有执行。

官方计量参考：[火山方舟 Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1)、[DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。实际字段和含义以所调用接口的当前官方文档及返回值为准。
